The gib on-chain format

The on-chain byte formats gib reads and writes. Binary dir and patch formats are specified in their own doc: ordfs-formats.html.

The record

A gib diff record is any single output — B protocol or ordinal inscription — holding a fixed binary envelope followed by the delta payload:

record :=
  [1B  version]        // format version, starts at 0x00
  [36B base outpoint]  // 32B txid + 4B LE vout, BSV-native serialization
  [..  vcdiff delta]   // RFC 3284, replayed against the base's resolved bytes
  • Base is any inscription — B protocol or ordinal; gib doesn't care which, and doesn't require the base to be gib-published.
  • A chain is records linked by base. Genesis = any inscription (a directory, a file, even a foreign ordinal); each record extends the previous tip.
  • No "replace" type by design: replacing content isn't extending a base — it's a new inscription (empty chain) plus a manifest cascade retargeting the entry.
  • No merge-by-reference: file chains are linear; conflicts are resolved by publishing a reconciliation record, and views merge by citing different tips.

Codec: vcdiff only

The diff-type registry is removed (decision 2026-09-18). Rationale: every record is one file's source→target transition, which is exactly vcdiff's unit — RFC 3284's COPY/ADD/RUN cover edit (its purpose), append (~6 bytes instruction overhead regardless of file size), and replacement, for text and binary alike, with no file-identity fields anywhere (identity is owned by the manifest and the base outpoint). Git diffs are multi-file documents by construction — the format we intentionally left behind with per-file chains — so "git diff" was always going to be a fake-friend byte. A single-value registry is confusion with a byte attached; broad reinterpretation, if ever needed, belongs in the version byte.

The directory

ordfs/dir binary manifests: one output per directory, entries name the current tip of each child's chain, and keeping tips current is what patches do — full re-inscribe of each touched directory, parents citing new child outpoints (cascade):

// editing js/app.js:
1. record R   { base: <app.js tip> }                       // new file tip
2. new js/ dir    { "app.js": → R, ... }              // full re-inscribe
3. new root dir   { "js": → new js/ outpoint, ... }    // full re-inscribe

Every reference points backwards; every state resolves by walking down from its root.

Content types

Records inscribe as ordfs/patch; directories as ordfs/dir (binary manifest — full re-inscribe per touched dir; JSON ord-fs/json is legacy-read). The record envelope above is the ordfs/patch payload. See ordfs-formats.html for both. New types use the non-hyphenated ordfs/ prefix; gib identity lives only in commit-token push-drop fields.
