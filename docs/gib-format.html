The gib on-chain format

One new thing: the record. Everything else is existing ord-fs.

The record

A gib diff record is any inscribed output ORDFS can serve — B protocol or ordinal inscription — holding a fixed binary envelope followed by the diff payload:

record :=
  [1B  version]        // format version, starts at 0x00
  [1B  diff type]      // codec registry below; 0x00 invalid
  [36B base outpoint]  // 32B txid + 4B LE vout, BSV-native serialization
  [..  diff payload]   // bytes as-is; text or binary per type
  • Base is any inscription — B protocol or ordinal; gib doesn't care which, and doesn't require the base to be gib-published.
  • A chain is records linked by base. Genesis = any inscription (a directory, a file, even a foreign ordinal); each record extends the previous tip.
  • No "replace" type by design: replacing content isn't extending a base — it's a new inscription (empty chain) plus a manifest cascade retargeting the entry.
  • No merge-by-reference: file chains are linear; conflicts are resolved by publishing a reconciliation record, and views merge by citing different tips.

Diff type registry

typenamemeaning
0x01gitstandard git diff text against the base's resolved content (default). Context-addressed hunks; binary files via git's base85 literal patches.
0x02vcdiffRFC 3284 binary delta replayed against the base bytes. Real deltas for binary files; requires the author to hold the base.
0x03appendpayload concatenated onto the base's resolved bytes. Authoring needs no knowledge of the base — for growing files (logs, WALs).

Adding a codec means adding a registry line; unknown types are a clean resolver error, not a silent misparse. Broad reinterpretation belongs in a new version byte, not a wider type field.

The directory

Ordinary ord-fs directory JSON, format unchanged — which is why ORDFS already serves gib trees. The only gib convention: an entry names the current tip of the entry's chain, and keeping that current is what records do:

// editing js/app.js:
1. record R   { base: <app.js tip> }                       // new file tip
2. record M1  { base: <js/ manifest tip> }  // js/ JSON diff: "app.js": → R
3. record M2  { base: <root manifest tip> } // root JSON diff: "js": → M1

Every reference points backwards; every state resolves by walking down from its root.

Content type

Records inscribe with content type application/x-gib.
